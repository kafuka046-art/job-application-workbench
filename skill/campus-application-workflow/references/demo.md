# 给朋友看的使用演示

这个 Skill 帮 Codex 按顺序做校招投递：**查公司与岗位 → 核实投递规则 → 用个人经历给岗位排序 → 你选岗位 → 制作简历和作品集 → 记录投递结果**。

它是一份工作方法，不内置岗位库、内推码或你的个人经历。岗位开放情况和规则要在使用当天查官网；每个人要提供自己的经历。以下“星河视频”和所有数字都是虚构演示。

## 开始使用：免安装或本地安装

**免安装试用**：解压分享包，在能读取本地文件的Codex中打开解压后的文件夹，告诉它：“先读取 `campus-application-workflow/SKILL.md`，按其中的流程工作；先建立我的资料库，不生成简历、不提交申请。”读取成功不等于已安装或自动发现Skill。

**本地安装（2026-10-08核对官方说明）**：

1. 复制整个 `campus-application-workflow` 文件夹到自己的用户级 `~/.agents/skills/`，或求职工作目录里的 `.agents/skills/`。不要在多个位置重复安装同名Skill。
2. Windows用户级路径通常为 `C:\Users\你的用户名\.agents\skills\campus-application-workflow\SKILL.md`；Mac/Linux为 `~/.agents/skills/campus-application-workflow/SKILL.md`。要保留 `references` 子目录，不能只复制SKILL.md。
3. 在支持该调用方式的Codex环境里用 `$campus-application-workflow` 或技能选择器调用；未出现时重启并检查当前产品的技能入口，不假定所有版本界面相同。

来源：[OpenAI官方Build skills说明](https://learn.chatgpt.com/docs/build-skills)。旧版本或其他产品按各自实际支持的目录与入口操作，不将本包当成已经发布的插件。

**其他聊天AI**：提供SKILL.md及当前需要的Demo/模板，作为流程提示使用。这不等于原生安装；没有联网、文件读写或浏览器能力的环境不能自动查岗位、导出文件或填写网页。先确认它能读取哪些资料，不能默认自动沿用Codex工具能力。

## 第一次使用：告诉它你的基本情况

把下面这段发给 Codex，替换括号中的内容：

```text
$campus-application-workflow
我是[毕业届别]，[学历/专业]，主要想投[方向]，可以去[城市]。
我的经历底稿在[文件路径]；如果没有底稿，请先带我建立最小事实库。
以后推荐岗位时，以“硬性条件是否满足、经历是否有证据、我的兴趣”为依据。
先不要生成简历。
```

Codex 会先读取你提供的资料；资料不足时，只问影响当前推荐的关键问题。

## 一次完整投递演示

### 第1轮：查岗位和规则

你说：

```text
帮我查星河视频有没有开2027届秋招。请以官网为准，检查完整岗位列表、我能投几个岗位、方向与志愿规则、不同岗位是否共用简历和修改资料的影响、附件要求，以及有没有可验证的内推码。先告诉我适合投什么，不生成简历。
```

你应该看到类似结果（下面仅演示结构）：

```text
官网岗位总数：18；已读取：18；未覆盖：0
符合硬性条件：6；值得细看：3
投递上限：2个（官网FAQ，查询日期...）
方向限制：这两个岗位允许同投；志愿依次流转（仅为虚构示例）
资料共享：在线简历和简历附件公司共用，作品集公司共用，无单独自我描述
更新影响：替换附件后，两岗面试官都会看到最新版本（仅为虚构示例）
内推码：未找到可验证信息

推荐1：内容运营——实习经历有直接证据，能力缺口较小
推荐2：产品运营——项目和数据经历可迁移，但缺少对口实习
不推荐：算法产品——学历或技术要求不满足

如果只能投1个，建议内容运营；如果能投2个，建议内容运营→产品运营。
两岗共用一份公司投递版，以内容运营为主线，补上产品运营所需的反馈与迭代证据。
请你决定最终岗位和顺序。
```

真实使用时，应附官网链接和查询日期。如果岗位列表只能看一部分，Codex 应标记“未核完”，不能假装已看全。共享或更新规则未知时，标记待核实；不能因为有2个岗位名额就默认上传2份独立简历，更不能通过试提交验证规则。

### 第2轮：你拍板，Codex给选材方案

你说：

```text
我选内容运营为首志愿，产品运营为第二志愿。先给我看这一份共用简历拟收录、可选、不收录的经历，逐项说为什么，两岗的核心要求怎么覆盖，以及简历和作品集准备怎么做。等我确认后再生成。
```

Codex 应给出：每段经历对应哪条JD、哪些数字需核实、简历板块顺序、简历内准备放哪些作品链接，以及完整作品集附件如何适配上传限制。先判断已有版本能否沿用；需要适配时，以主投岗位决定顺序，不把两份简历拼接，不为公司措辞调整修改经历事实底稿。

### 第3轮：确认材料

你说：

```text
选材方案确认。按我的简历模板生成投递文件，并检查事实、重点加粗、排版、链接和附件。给我明确的上传顺序。
```

这时才进入简历制作。能否生成PDF、DOCX以及附件形式，取决于你使用的工具和招聘平台限制。

### 第4轮：投后登记

你说：

```text
这家公司已经投完。记录岗位、日期、使用的简历版本、上传附件、内推码状态和后续进度。
```

下次收到笔试或面试邀请，再让它根据当时投递的岗位和材料继续跟进。

## 两个常见提醒

- **不用一次说完所有资料。** 先给毕业信息、方向和已有经历；资料库可以逐次补。
- **内推码、岗位数量、截止时间都可能变化。** 让 Codex 提供来源和查询日期；无法验证就如实标记。
