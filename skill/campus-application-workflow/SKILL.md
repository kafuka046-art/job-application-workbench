# 校招投递工作流

按候选人的实际目标推进：找到可投岗位，确认规则与优先级，制作可信材料，保存投递记录。每个人的经历、版式偏好、求职方向和个人限制从其自己的资料读取；不要套用他人的身份或项目。

## 起点与资料

- 先确定求职届别、学历、专业、可去城市、方向偏好、硬性排除条件，以及求职者已有的经历底稿、作品与投递记录。缺少资料时，先用 [录入模板](references/templates.md) 建立最小事实库；只追问影响当前决策的缺口。
- 每段经历记录：组织/项目、角色、起止时间、本人动作、结果与数字、证据链接、真实性边界。区分真实工作、独立作品和模拟方案。经历底稿是唯一事实来源；新经历先核对事实，再启用到投递材料。
- 建立个人规则表：事实规则、格式偏好、禁写内容、作品集策略、确认节点。候选人自己的明确要求优先于通用建议。

## 1. 发现公司与读取岗位

用户只问“现在什么公司开了”时，查询当前批次和官网开放状态，按其学历、方向、城市筛出可研究公司；标明查询日期、来源、仍需核实项。招聘动态、岗位、截止时间和规则会变化，执行时必须实时核验，不能沿用旧清单。

用户指定公司后，优先读官网招聘项目、岗位列表、具体JD和FAQ；无法直接访问官网时，可结合用户截图、官方公告和其他可追溯来源。记录官网展示总数、实际读取数、筛选范围和未覆盖部分。若分页、登录或动态加载导致无法穷尽，就明确写“未核完”，不能称已看完全部岗位。

逐项核实：届别/毕业时间、学历与专业门槛、城市、岗位编号、开放/截止时间、可投岗位或志愿数、志愿顺序、投后能否修改、测评/笔试影响、附件数量/格式/大小、自我描述或作品要求。对每条关键规则保存来源链接或截图说明和查询日期；找不到就写“待核实”。

**选岗与制作材料前，先核查多岗位的资料共享规则**：分别确认在线简历、简历附件、自我描述及作品集是公司共用、岗位独立还是尚未核实；修改资料或替换附件是否影响已投岗位、面试官是否看到最新版本，也要单独核实。同步检查方向/子方向上限、志愿依次流转还是并行，以及投后不可更改的限制。岗位数量不等于独立简历数量。依据官网FAQ、已登录表单或用户截图记录证据与日期；不要为验证而提交申请。规则未明时可继续研究岗位，但不得假定各岗独立生成多份材料、替换可能共用的已投附件或直接提交。

内推码只采用能说明来源、适用招聘项目和时效的码。公开码无法确认有效时标记“未验证”，不承诺可用；不要虚构码，也不要为了等码延误已确认的投递。若用户自有内推码，以其提供的信息为准，同时检查是否必须在投前填写。

## 2. 排序岗位并请用户拍板

先剔除学历、届别等硬性不符岗位，再对可投岗位比较：JD核心任务与经历证据的直接程度、能力缺口、城市/兴趣、竞争强度、投递上限与志愿顺序。强证据、相邻证据和缺口分开写；不能用关键词重合度冒充录用概率。

多岗位选择同时评估组合：求职者能做多个方向，不代表平台允许同时投这些方向，也不代表应该填满名额。共用资料时优先选择能够用同一条能力主线支撑的岗位；说明跨方向组合的取舍与首志愿机会成本。按官网的方向分类核算限制，不凭职位名称自行分类。

输出覆盖范围、推荐排序、每岗“为什么推荐/为什么不推荐”、最大优势与风险，并在只能投一个和可投多个两种情形下给出明确建议。岗位池未核完时，结论标为暂定。**最终岗位与志愿顺序由求职者确认**；用户明确选择后再进入材料制作。用户只要研究或比较时，不擅自生成简历或提交投递。

## 3. 从底稿选材并制作材料

针对已选JD列出拟收录、可选、不收录的经历及每项理由，指出顺序、需补证据和材料形态。重要取舍先展示给用户；其确认后按原始事实改写。允许调整顺序、压缩、展开和换岗位语言；不编造数据、职责、时间或结果，不把“参与”升格为“主导”，不把模拟作品写成真实商业经历。

先确定“沿用、轻改或重新适配”，不要默认每岗都要重做。若多个岗位共用简历，制作一份公司投递版：由主投岗位决定定位和顺序，保留其他已选岗位需要的真实证据，不能把数份简历拼接或往作品集塞入多份简历来绕过限制。资料独立时才按需要分别适配。公司选材与表达调整不改动经历事实底稿；只有用户确认的新事实才回写底稿。可能覆盖已投资料的替换须先说明影响，并获用户确认。

简历排版遵守求职者的模板与偏好。重点突出岗位标题、关键动作、数字和成果；检查页数、断行、重叠、字体、时间顺序及可点击链接。没有被要求时，不自行添加求职意向、到岗承诺或未经核实的称号。导出何种文件取决于平台要求和求职者偏好；如需DOCX/PDF，使用相应文档工具生成并检查最终渲染。

**区分两种作品集策略**：简历内链接按目标岗位选最相关的；单独的作品集附件默认保留完整已批准作品，受平台数量、大小、格式限制时，先给压缩、合并或上传顺序方案。作品、模拟策划和真实经历分别标注。只上传或交付求职者授权的材料，不把敏感原始素材夹入分享包。

投前进行事实、JD、格式、链接和附件检查：公司/岗位名无串版；数字有来源；时间与学历一致；链接能打开；符合平台限制。必要时同步准备网申自我描述，但不得与简历事实冲突。

## 4. 投递与归档

只有用户明确授权提交时才执行投递；否则交付可上传材料和填写说明。投后登记公司、岗位编号、城市、志愿顺序、日期、内推码及验证状态、简历版本、附件清单、资料共享与投后更新规则、状态与下一步时间。保存当次材料的不可变副本，以便面试时回查；更新底稿不覆盖历史投递版。若招聘系统展示最新共用资料，另记每次替换时间、涉及岗位和新旧版本，不能把本地历史副本当成面试官仍在看的版本。

复杂投递可使用 [输出与记录模板](references/templates.md)。每次按用户当下问题停在合适阶段：发现、公司岗位审查、岗位决策、材料制作、投后登记。不要把整条流程压成一次不可审查的自动运行。

首次使用者问“怎么用”或要求演示时，参考 [使用演示](references/demo.md)；演示中的公司和数据均为虚构，不可当作真实招聘信息。
